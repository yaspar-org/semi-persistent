# Cross-engine benchmark suite

This directory documents the seventeen-program comparison set translated into
our surface language and timed against egglog at its pinned commit. The
per-benchmark ledgers record every semantic difference between the programs
being compared, and
`records/campaigns/final-r6-tables.md` is the newest retained historical
campaign. It predates the current implementation and used process medians
without bootstrap confidence intervals, so it is not current performance
evidence.

The programs and the runners live in the crates that own them:

| what | where |
|---|---|
| our translations | `egraph/tests/egg/bench/<name>.<encoding>.egg` |
| egglog's programs | `scripts/egglog-compare/programs/<name>.egglog.egg` |
| the manifest both runners read | `egraph/benches/corpus.toml` |
| our timing harness | `egraph/benches/corpus.rs` |
| the cross-engine script | `scripts/egglog-compare/compare.py` |
| ledgers, campaigns, protocol | this directory |

Two status words are used throughout, defined in `methodology.md`: a benchmark
or configuration is **dropped** when it is out of the comparison with the
reason recorded, and **postponed** when it is blocked on a measured cost with
the condition that revives it.

`array` and `subsume` are **BLOCKED carriers**: complete rules
translations whose first line is `;; BLOCKED: <missing feature>` (the
`.egglog.egg` halves keep their upstream first lines). `array` needs
datalog relations as rule atoms (its `neq` relation is load-bearing);
`subsume` runs but our `:subsume` excludes a node from matching, not from
extraction, so its extraction check diverges from egglog (measured in
`subsume.deviations.md`). They never enter a campaign: both carry
`blocked = "<missing feature>"` in `egraph/benches/corpus.toml`, which the
timing harness, the comparison script, and the test registration all skip, so
promoting a carrier is one manifest edit plus removing the header. Each ledger
states the condition that unblocks it. `resolution`'s native column is the first ACI
(`:assoc-comm-idem`) configuration in the set, and `acgen` is a generated
instance whose ledger records the generator invocation and the N=13
measurements behind the shipped N=11.

`repro-herbie-vanilla` (ranked 4) is dropped: at the pinned commit it is a
typed-lowering unsoundness reproduction with no checks, not a benchmark;
`repro-herbie-vanilla.deviations.md` records the characterization.

`eqsolve`'s native encoding is validated but excluded from timed tables: all
ten of its checks pass under `--lazy-ac-eqs` in one 484 s run, against 123 ms
for its rules encoding, so the file carries a `REQUIRES` header and no timing
appears in any campaign. `eqsolve.deviations.md` has the measurements.

`matrix` ships two native configurations, which is why it has four rather than
three: `matrix.native.egg` carries native AC on `Times` only, and
`matrix.native-A.egg` adds native A on `MMul` and `Kron` with their four
associativity rewrites deleted. The pair is what isolates the A-only half of
the signature, the property this benchmark was selected for. Read
`matrix.deviations.md` before drawing an A-only conclusion from this set.

`integer_math` and `herbie` are scoped columns: a reduced program, identical
in every configuration, standing in for the upstream benchmark. Their timings
are not comparable to anything upstream calls by those names. Both ledgers
open with that warning and state what the scoping removes; for `integer_math`,
537 term nodes down to 100 at the run budget.

| `<name>.rules.egg` | ours | A/C supplied as explicit rewrite rules, their encoding |
| `<name>.native.egg` | ours | A/C carried by the operator declaration, the A/C rules deleted |
| `<name>.native-A.egg` | ours | matrix only: the above, plus native A on its two A-only operators |

## Campaigns and harnesses

Two runners share `egraph/benches/corpus.toml`, which is the single list of
what exists and what may run.

`egraph/benches/corpus.rs` times our engine alone, in process, under Criterion.
Each iteration builds a fresh interpreter and includes parsing, sortchecking,
and execution. Criterion supplies warm-up, adaptive iteration counts, outlier
analysis, bootstrap confidence intervals, and saved-baseline comparisons.
There is no fixed wall-clock or ratio verdict: the former five-sample,
25%-ceiling gate changed outcome with host load and was retired. Correctness of
every corpus program remains in the ordinary Rust test suite.

`scripts/egglog-compare/compare.py` is the cross-engine half. It clones egglog
at the revision pinned in the manifest into a temporary directory, builds it,
runs the comparable subset on both engines under the protocol below, and
writes every timed sample, aggregate statistics, and provenance binding the
data to exact binary hashes, source state, commands, timestamps, protocol, and
machine metadata. The comparable subset is exactly the manifest entries that
carry an `egglog` counterpart and no `blocked` value.

This script is useful for reproducibility, structural counters, and historical
process measurements, but its median-and-dispersion report is not the release
performance gate. A new machine-sensitive performance claim must benchmark the
same-revision binaries with Criterion, retain Criterion's bootstrap confidence
intervals, and record the same provenance.

Campaign records live in `records/campaigns/`: `final-r6-tables.md` is the
newest retained historical campaign. Its 750-row sample file, 75-row aggregate
file, and v3 provenance record are the first campaign artifacts that satisfy
the raw-data retention protocol. `final-r5` is the first campaign produced by
an earlier version of `compare.py`, but it retained aggregates only and
incomplete provenance. r1 through r5 remain archived because ledgers and
experiment write-ups cite them. Each report states its own source and
environment scope.

`scripts/egglog-compare/gen-herbie.py` regenerates herbie's egglog and rules
programs and `herbie-dropped.txt`, the verbatim listing of every form the
scoping removes;
`herbie.native.egg` is hand-derived and its ledger is the record of each
translation decision.

`addac-sweep.md` reports the add-ac width-scaling sweep that answers part (b)
of the convergence target in
`egraph/doc/design/20-index-selectivity-and-delta-suffixes.md`: the
`math-add-ac` block generalized to sum width n = 7..20, three configurations
per width. `scripts/egglog-compare/gen-addac-sweep.py` writes those programs
and `records/addac-sweep.csv` holds the per-run values. Native AC holds at 4n - 3 nodes and one iteration
across the whole range while the rules encoding reaches 37 902 nodes at
n = 20.

`records/semi-persistence/` quantifies what push/pop is worth: the survey of how
each engine implements it, a micro-benchmark of
push/assert/run/check/pop cycles over bases of 1e4 to 1e6 nodes on both
engines, the internal restore-versus-re-run baseline that needs no
cross-engine caveat, and `calc.egg` as the multi-block macro exhibit. Read
`records/semi-persistence/semi-persistence.md`; its sections 11 and 12.3 state what
the numbers do and do not establish (section 8's asymptotic reading is
retracted there).

The index-build and matching-throughput measurements are consolidated in
`egraph/doc/design/20-index-selectivity-and-delta-suffixes.md`; container-level
costs and invariants are in `containers-verus/doc/design/15-dense-span-map.md`.

Read the ledgers before the numbers. `math-microbenchmark.deviations.md` in
particular records a deviation large enough to change how its native column
may be read: eleven of its rules are restated in n-ary form, because a binary
pattern against a variadic AC operator is an exact pattern and would silently
stop firing on flat nodes of arity three or more.

## Protocol

Both engines are built in release mode and driven as separate processes, so
the wall time includes process start, parse, sortcheck, saturation, and the
statistics commands. Each (benchmark, configuration) pair runs 2 warmups then
10 timed runs; the summary reports the median. A campaign is one such pass
over the whole set at one engine commit; a run is one timed invocation.
This describes the archived `compare.py` campaign protocol, not the Criterion
protocol required for a new performance claim.
Ours runs with default engine flags: in particular `--union-by rank`, the
default the campaigns are timed under; any table timed under a different
`--union-by` value states it, per `methodology.md`.

egglog runs `-j 1 --mode no-messages`: threading is their only nondeterminism
source, and `no-messages` suppresses the output of `print-size` and
`print-stats`. The timed JSON still supplies iteration records. Because egglog
7b1adf2 does not put table cardinalities in that JSON, the runner performs one
normal-mode cardinality probe per benchmark outside all timings. Egglog does
not expose e-class counts. Ours runs with default flags plus the `--types`
groups each program's header names; herbie needs `machine,bignum`.

Our engine is timed under both saturation strategies, because the choice is
not settled by a default: `src/main.rs` makes naive the default and
`--use-semi-naive` the opt-in, so `ours-*-naive` is the shipped configuration
and `ours-*-semi` is reported beside it.

Two asymmetries in the timing, both stated rather than corrected. First, our
timed runs compute and print `print-size` while egglog's `no-messages` mode
skips that work: at 1.2 M nodes the listing is a linear pass and 14 lines of
output. Second, both engines write their statistics JSON during the timed
run, so that cost is symmetric.

Node counts are not measured the same way by the two engines, and the
difference runs in egglog's favour: their `print-size` reports table
cardinality after rebuild, ours reports stored nodes, so a node that
congruence turned into a duplicate is still counted by us and not by them.
`eqsat-basic.deviations.md` demonstrates this on a two-line probe. Our totals
also include one node per distinct interned literal, which theirs never
count.

## Re-running

Our side alone, no egglog needed:

```
cargo bench -p semi-persistent-egraph --bench corpus
cargo bench -p semi-persistent-egraph --bench corpus -- calc
EGRAPH_CORPUS_HEAVY=1 cargo bench -p semi-persistent-egraph \
  --bench corpus -- acgen

# Same-host before/after comparison
cargo bench -p semi-persistent-egraph --bench corpus -- \
  --save-baseline before
cargo bench -p semi-persistent-egraph --bench corpus -- \
  --baseline before
```

Retain Criterion's estimate and confidence interval together with the source
revision, host state, and command. A result is evidence, not a machine-agnostic
CI gate.

Both engines. The script builds our binary and clones and builds egglog at the
pinned revision itself, so the only prerequisite is a network fetch:

```
python3 scripts/egglog-compare/compare.py --label <name> --require-stats
python3 scripts/egglog-compare/compare.py --require-stats \
  --benchmark math-microbenchmark
python3 scripts/egglog-compare/compare.py --require-stats \
  --keep-egglog ~/tools/egglog
```

`--keep-egglog` reuses a checkout instead of cloning and refuses to record the
run if that checkout is not at the pinned revision. `--ours` skips building our
side and records the supplied binary's exact identity. Results land under
`records/` named after `--label`: `-samples.csv`, `-results.csv`, and
`-provenance.json`. Publication campaigns use `--require-stats`.

To run one program by hand:

```
target/release/semi-persistent egraph/tests/egg/bench/math-microbenchmark.native.egg --types machine
<egglog>/target/release/egglog -j 1 scripts/egglog-compare/programs/math-microbenchmark.egglog.egg
```

## Building egglog when cargo cannot reach crates.io

On the machine that produced these numbers, `cargo` could not open a
connection to `index.crates.io` while `curl` to the same host succeeded, so
egglog's dependencies were vendored by hand: read `name`, `version` and
`checksum` for every registry package in egglog's `Cargo.lock`, fetch
`https://static.crates.io/crates/<name>/<name>-<version>.crate`, extract each
into `vendor/<name>-<version>/` with a `.cargo-checksum.json` holding that
checksum, and point `.cargo/config.toml` at the directory:

```toml
[source.crates-io]
replace-with = "vendored-sources"
[source.vendored-sources]
directory = "vendor"
```

`cargo build --release --offline -p egglog` then succeeds. This is recorded
because the egglog side of the comparison cannot be reproduced without it on
a similarly restricted machine. The `.crate` files stay useful: keeping the
download cache means a later re-vendor needs no network at all.

egglog pins toolchain 1.91.0 and the binary is built at that pin: 8.82 MB,
byte-for-byte agreement with the committed ledgers on the three benchmarks
checked (eqsat-basic 11 nodes / 3 iterations, math-add-ac 1 939 / 7,
addac-n7 451).

## What the comparison does not cover

One machine, no CPU pinning, no isolation from other load. The historical
campaign used an informal "under about 10%" noise heuristic; that is not a
current decision threshold because the process runner did not compute
confidence intervals. `final-r6` additionally records substantial starting
load, so its report gives a stronger absolute-time qualification. Current
performance decisions require a same-revision Criterion comparison with
retained bootstrap confidence intervals. No proof or term-encoding mode on
either side.
egglog's own performance suite (`scripts/bench.py`) is lattice, container and
schedule workloads outside the intersection; the comparison covers the eqsat
core of their test corpus, not their headline benchmarks, and conversely
those workloads exercise machinery we do not implement.
