# Public exec functions that still expose a `requires` clause.
# Entries may only be removed. The list is EMPTY: every public exec function
# of the crate is total (its only precondition, if any, is the receiver's own
# well-formedness `wf()`/`cursor_wf()`/`cursor_ok()`/`cwf(c)`, upheld by every
# constructor and operation — see tools/check_partial_api.py).
#
# How the former floors drained (doc/future/total-api-plan.md):
#   - type-class law (map.rs::new, obeys_key_model): a conditional
#     postcondition (`obeys_key_model::<K>() ==> m.wf()`), nothing to check;
#     tagged.rs trait laws: `repr_wf(r) ==> ...` conditional contracts.
#   - unreachable receivers (DiffStore protocol methods): sealed onto the
#     crate-private supertrait `diff_store_ops::DiffStoreOps` (module
#     `pub(crate)`), so the public `DiffStore` carries only total methods.
#   - component boundary (circular_list.rs::{splice, splice_absorb}): a
#     verified walk of the absorbed ring refuses a same-ring splice; the
#     e-graph merge uses the crate-private walk-free cores.
#     sparse_set.rs::restore: the snapshot archive is part of `wf`, so the
#     guard checks only token validity + equal frame indices.
#   - rechecked layouts (bplus_layout.rs NodeLayout primitives): the runtime
#     mirrors became refuse-guards and the contracts conditional, the pattern
#     `leaf_fill_keys` already used.
#   - guard.rs::check_precondition, capture_bits.rs::set_true and the other
#     internal primitives: `pub(crate)`.
#   - capability token (tagged.rs::from_repr_clean, requires an untagged
#     repr): added 2026-09-25 for the unmasked id decode, retired the same
#     day by a `tagged::CrateOnly` parameter. The token's constructor is
#     `pub(crate)`, so only this crate's verified code can call the method;
#     consumer crates still implement it through the id macros. It could not
#     be sealed like DiffStoreOps because consumer crates implement `Tagged`.
